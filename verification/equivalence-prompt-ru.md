# Задача: проверить, что формулировка на Lean 4 утверждает ровно то же, что математическая теорема

Вы проверяете формализацию. Единственная задача — решить, **равносильна ли логически** формулировка
на Lean (ниже) математической теореме (ниже). **Не** пытайтесь доказать или опровергнуть саму
теорему и не оценивайте доказательство: доказательство на Lean проверено машиной (нет `sorry`,
используются только стандартные аксиомы `propext`, `Classical.choice`, `Quot.sound`). Единственный
остающийся риск — что формальная формулировка означает не то же, что математическая. Будьте
придирчивы и точны.

## 1. Математическая теорема

Пусть `P = [0,p₁]×[0,p₂]×[0,p₃]`, где `pᵢ > 0`, и `Q = [0,q₁]×[0,q₂]×[0,q₃]`, где `qⱼ ≥ 0`
(замкнутые коробки в евклидовом трёхмерном пространстве). `Q` *помещается в* `P`, если `f(Q) ⊆ P`
для некоторой изометрии `f` пространства `ℝ³` (разрешены повороты, сдвиги и отражения).

Для `x ≥ y ≥ 0`, `s ≥ 0`:

```
H(x, y; s) = y                                                   если x ≤ s
H(x, y; s) = min( x, (2xys + (x² − y²)·√(x² + y² − s²)) / (x² + y²) )   если x > s
```

и для произвольных `u, v ≥ 0`: `H(u, v; s) = H(max(u,v), min(u,v); s)`.

`Fit(a, b; u, v)` означает: `min(u,v) ≤ a` и `H(u, v; a) ≤ b`.

**Критерий NC(p, q):** существуют перестановка `(i, i', i'')` осей `(1,2,3)` и перестановка
`(j, k, l)` рёбер `(1,2,3)`, такие что

```
min(q_k, q_l) ≤ p_i   и   Fit(p_{i'}, p_{i''}; q_j, h*),   где h* = H(q_k, q_l; p_i).
```

**Теорема.** Если `p₁, p₂, p₃ > 0` и `q₁, q₂, q₃ ≥ 0`, то `Q` помещается в `P` тогда и только
тогда, когда выполнено `NC(p, q)`.

## 2. Формулировка на Lean 4 (дословно; Lean 4 + Mathlib, индексы `0, 1, 2`)

```lean
namespace Boxes
open Real

/-- Euclidean space `ℝ³`. -/
abbrev E3 := EuclideanSpace ℝ (Fin 3)

/-- The closed box with edges `q` along the coordinate axes. -/
def box (q : Fin 3 → ℝ) : Set E3 := {x | ∀ i, 0 ≤ x i ∧ x i ≤ q i}

/-- The box with edges `q` fits into the box with edges `p`. -/
def Fits (p q : Fin 3 → ℝ) : Prop := ∃ f : E3 ≃ᵢ E3, f '' box q ⊆ box p

def stripOK (u v s : ℝ) : Prop := min u v ≤ s

noncomputable def stripH (u v s : ℝ) : ℝ :=
  let x := max u v
  let y := min u v
  if x ≤ s then y
  else min x ((2 * x * y * s + (x ^ 2 - y ^ 2) * √(x ^ 2 + y ^ 2 - s ^ 2)) / (x ^ 2 + y ^ 2))

def Fit2 (a b u v : ℝ) : Prop := stripOK u v a ∧ stripH u v a ≤ b

def NCcase (p q : Fin 3 → ℝ) (σ τ : Equiv.Perm (Fin 3)) : Prop :=
  stripOK (q (τ 1)) (q (τ 2)) (p (σ 0)) ∧
  Fit2 (p (σ 1)) (p (σ 2)) (q (τ 0)) (stripH (q (τ 1)) (q (τ 2)) (p (σ 0)))

def NC (p q : Fin 3 → ℝ) : Prop := ∃ σ τ : Equiv.Perm (Fin 3), NCcase p q σ τ

theorem fits_iff_NC (p q : Fin 3 → ℝ) (hp : ∀ i, 0 < p i) (hq : ∀ i, 0 ≤ q i) :
    Fits p q ↔ NC p q
```

Справка по обозначениям Lean/Mathlib:
* `EuclideanSpace ℝ (Fin 3)` — это `ℝ³` с евклидовым расстоянием; `x i` — `i`-я координата.
* `E3 ≃ᵢ E3` — тип изометрических биекций `E3` на себя (`IsometryEquiv`).
* `f '' S` — образ множества `S` при отображении `f`; `⊆` — включение множеств.
* `√t` — это `Real.sqrt t`, определённый для всех вещественных чисел и равный `0` при `t < 0`.
* `Equiv.Perm (Fin 3)` — тип перестановок множества `{0, 1, 2}`.
* `min`, `max` на `ℝ` — обычные; `if … then … else …` — обычный разбор случаев.

## 3. Что проверить (ответьте на каждый пункт)

1. Совпадает ли `box q` с `[0,q₀]×[0,q₁]×[0,q₂]` (замкнутая коробка, параллельная осям, с вершиной в
   начале координат)?
2. Совпадает ли `Fits p q` с «Q помещается в P» в смысле определения выше? В частности: равносильна
   ли квантификация по изометрическим **биекциям** `E3 ≃ᵢ E3` квантификации по всем изометриям `ℝ³`?
   Важно ли для коробок, что разрешены отражения?
3. Совпадает ли `stripH u v s` с `H(u, v; s)` при всех `u, v ≥ 0`, `s ≥ 0`, включая граничные случаи
   (`x = s`, `y = s`, `y = 0`, `x = y`, `u = v = 0`)? Может ли под корнем оказаться отрицательное
   число в той ветви, где корень используется?
4. Совпадает ли `Fit2 a b u v` с `Fit(a, b; u, v)` (обратите внимание на порядок аргументов)?
5. Совпадает ли `NC p q` с критерием `NC(p, q)`: точно ли соответствие между `σ, τ` и
   `(i, i', i'')`, `(j, k, l)` (каждая математическая проверка — некоторый `NCcase` в Lean, и наоборот)?
6. Совпадают ли гипотезы `hp`, `hq` теоремы `fits_iff_NC` с `pᵢ > 0`, `qⱼ ≥ 0` — ничего не добавлено
   и ничего не упущено?
7. Есть ли ещё какой-нибудь способ, которым формулировка на Lean слабее, сильнее или пуста по
   сравнению с математической теоремой (неявное приведение типов, сдвиг индекса на единицу,
   определение, которое тривиально истинно или ложно)?
